# 765Radical：8×8キャラクター編成ルール（試作版）

> **保管場所:** 公開リポジトリ `structure-play` の `765-radical-dev` ブランチのみ。**GitHub Pages／mainには反映しない**。

## キャラクター64種類

行が数字0〜7、列が8種類の能力のため、8×8＝64種類のキャラクター候補を実装。
各数字は「能力なし」または「能力1種類」のいずれかを選び、全8数字を1チームとして編成する。能力なしの数字はコスト0。
プレイヤーAとプレイヤーB（CPU）の編成はそれぞれ独立で、2回戦で先後・色が入れ替わっても編成を維持する。

| コード | 名称 | コスト | 場に出した際の効果 |
|---|---|---:|---|
| E1 | Encallege-1 | 1 | 盤上の自分の他のコマ**1枚**を+1 |
| D1 | Discourage-1 | 1 | 盤上の相手のコマ**1枚**を−1 |
| E2 | Encallege-2 | 2 | 盤上の自分の他のコマ**1枚**を+2 |
| D2 | Discourage-2 | 2 | 盤上の相手のコマ**1枚**を−2 |
| E3 | Encallege-3 | 3 | 盤上の自分の他のコマ**1枚**を+3 |
| D3 | Discourage-3 | 3 | 盤上の相手のコマ**1枚**を−3 |
| SW | SWITCH | 2 | **この手で置いたコマ**と、盤上の自分の既存コマ1枚の位置を交換（現在値と基礎値を両方保持） |
| DS | DUBBLESTRIKE | 3 | 発動したラウンドは、通常の「自分の出力5つの最大値」ではなく**上位2つの合計**を自分の得点とする |

**総コストは各チーム3以下**。高コストの能力を選ぼうとして上限を超える場合は、選択を拒否して変更しない。
初期編成は両チームとも「数字4にE1、数字6にD1」で合計コスト2。好きな数字・効果に変更可能。

## 能力の対象／処理

- E／D／SWの対象選択は**コマを置いた直後**。盤上の既存コマから必ず1枚だけ選ぶ。
- 対象がない場合は不発。コマの配置自体は有効。
- 数値は0より小さくならない。すでに0のコマにDを使っても0。
- 発動はそのコマを置いた時1回のみ。効果は持続し、同じ対象に別の効果を重ねられる。
- 能力を持つ数字の選択は元の数字0〜7の使用回数を管理。途中で現在値が変わっても基礎数字の持ち駒は増減しない。
- SWITCHは今回の配置コマと既存の自分のコマの**座標を入れ替える**。2枚の基礎数字・現在値・能力はそれぞれのコマに付いて移動する。
- DUBBLESTRIKEはターゲット選択をせず、置いた後からそのラウンドの得点計算を上位2本の合計に変更する。自身は二重に計算しない。得点対象の線の色は変わらない。

## 操作フロー

1. Radicalを開くと編成画面が表示される。
2. 表の数字（行）×能力（列）からキャラクターを選ぶ。選択済みのセルをもう一度押す／「効果なし」を押すと解除。
3. 「プレイヤー A」「プレイヤー B／CPU」タブで両チームを編集。右上のコスト表示と最下部の編成確認を参照。
4. 「編成完了 → 対戦へ」を押すとゲームへ戻る。
5. 対戦画面の「キャラクター編成」で再編集可能。変更がある場合は対局が最初からやり直しになる。

## 検証

- PlaywrightによるChrome相当のブラウザ試験: 8行×8列＝64選択肢表示
- コスト3以内の編成を許容し、コスト4になる割当は拒否
- E／D対象の単体加減算、SWITCHの2枚の位置交換
- DS発動後の赤青各出力上位2本／最大値の得点照合（先後交代する2ラウンド）
- CPU vs CPU Lv.1で32手完走し、履歴32件を確認、JavaScript例外なし
- CPU Lv.10の全強度再調整およびヒントの全局面厳密性は**未検証**。推奨値は序中盤では近似
